## Descrição

Implementar operações CRUD (Create, Read, Update, Delete) para empresas no backend Express com autenticação JWT e Row Level Security via tabela `usuario_empresa`. Usuários conseguem gerenciar apenas empresas atribuídas a eles.

Resultado: Endpoints `/api/empresas` (GET, POST), `/api/empresas/:id` (GET, PUT, DELETE) funcionais, EmpresaService com validações, testes de CRUD e permissões.

## Acceptance Criteria

### Create Endpoint (POST /api/empresas)
- [ ] `POST /api/empresas` aceita `{ cnpj, nome }` (JSON)
- [ ] Requer JWT válido (autenticação obrigatória)
- [ ] Valida CNPJ (formato básico: 18 caracteres, apenas números e pontuação)
- [ ] Valida nome (não vazio, máx 255 caracteres)
- [ ] Cria registro em tabela `empresas` com `responsavel_id = userId do token`
- [ ] Cria registro em `usuario_empresa` (associação do usuário)
- [ ] Retorna `{ id, cnpj, nome, responsavel_id, ativa, criado_em }` em sucesso (201)
- [ ] Retorna erro 400 se CNPJ duplicado ou campos inválidos
- [ ] Retorna erro 401 se sem token

### Read Endpoints (GET /api/empresas, GET /api/empresas/:id)
- [ ] `GET /api/empresas` retorna lista de empresas do usuário autenticado
- [ ] Filtra por `usuario_empresa.usuario_id` (Row Level Security)
- [ ] Retorna `[{ id, cnpj, nome, responsavel_id, ativa, criado_em }]` (array)
- [ ] Retorna erro 401 se sem token
- [ ] `GET /api/empresas/:id` retorna detalhes de uma empresa (se acesso)
- [ ] Verifica se usuário tem acesso via `usuario_empresa` (RLS)
- [ ] Retorna 404 se empresa não existe ou sem acesso
- [ ] Retorna 401 se sem token

### Update Endpoint (PUT /api/empresas/:id)
- [ ] `PUT /api/empresas/:id` aceita `{ cnpj?, nome?, ativa? }` (parcial)
- [ ] Requer JWT válido
- [ ] Verifica RLS: usuário só pode atualizar sua própria empresa
- [ ] Valida CNPJ se fornecido (formato)
- [ ] Valida nome se fornecido (não vazio)
- [ ] Atualiza apenas campos fornecidos (parcial update)
- [ ] Atualiza `atualizado_em` timestamp
- [ ] Retorna empresa atualizada em sucesso (200)
- [ ] Retorna 404 se empresa não existe
- [ ] Retorna 403 se sem permissão (RLS violation)
- [ ] Retorna 401 se sem token

### Delete Endpoint (DELETE /api/empresas/:id)

- [ ] Requer JWT válido
- [ ] Verifica RLS: apenas criador pode deletar

## Dev Notes

### RLS Strategy (Row Level Security)

Row Level Security é implementado via **tabela de junção** `usuario_empresa`:

```typescript
// Em getEmpresas(userId)
const result = await pool.query(`
  SELECT e.* FROM empresas e
  INNER JOIN usuario_empresa ue ON e.id = ue.empresa_id
  WHERE ue.usuario_id = $1
`, [userId]);

// Usuário só vê empresas onde existe um registro em usuario_empresa
```

**Important:** RLS é implementado em lógica de aplicação, não em PostgreSQL RLS policies (será feito em STORY-1.4).

### CNPJ Validation

Validação básica (STORY-2.1):
- Formato: `XX.XXX.XXX/XXXX-XX`
- Regex: `/^\d{2}\.\d{3}\.\d{3}\/\d{4}\-\d{2}$/`
- Apenas verifica formato, NÃO calcula dígito verificador (pode ser feito em STORY-2.3)

### Cascade Delete

Quando uma empresa é deletada:
- DELETE em `impostos_mensal` (CASCADE já configurado em schema)
- DELETE em `usuario_empresa` (CASCADE já configurado)
- DELETE em `empresas`

Aplicação não precisa fazer delete manual, banco faz.

### Error Handling

```typescript
// CNPJ duplicado → banco retorna erro UNIQUE
// Aplicação captura e retorna 400 com mensagem clara

// Empresa não existe → aplicação retorna 404

// RLS violation → aplicação retorna 403 (Forbidden)
```
